# 研究任务记录

执行状态：计划，尚未执行。信息状态：READY 或 NEEDS_USER_INPUT（由实际证据判断）。
将下列字段替换为本任务的真实内容；计划、授权和已完成结果分别记录。

| 字段 | 内容 |
| --- | --- |
| 任务/Issue | 记录 Issue URL 或本地任务标识 |
| 任务类型/路线 | A 官方复现、B 自定义数据、C 算法开发、D 分析仿真，或协作维护；混合/失败分析写明组合 |
| 研究问题 | 写明要回答的问题或建立的能力 |
| 目标结果 | 可观测结果与成功/失败判据 |
| 主要依据 | 论文标识与版本、官方实现 commit 或需求来源 |
| 代码基线 | 实际 repository 和 commit |
| 范围 | 将修改的组件及明确排除的算法/实验 |
| 输入材料 | 可访问的源码、数据版本和说明；不适用项明确标记，不强制官方 Demo |
| 数据/实验契约 | 相关的 Observation、Action、单位/坐标系、采样频率/对齐、split、训练目标和评价协议；不适用则注明 |
| 已核查证据 | 仓库文档、元信息、历史实验及主要来源；区分定位符与实际读到的证据 |
| 信息判断 | 是否足够完成下一步；READY 或 NEEDS_USER_INPUT，并说明依据 |
| 资源预算 | CPU/GPU 时间、数据访问、硬件许可；未授权则不运行 |
| 验证计划 | 各层检查命令、所需输入、预期可验证条件 |
| 审核决策 | 主 Agent 根据目标、diff 和科学风险记录 L0/L1/L2、触发原因、范围及审核记录位置 |
| 产物 | 文件/报告位置；不在此放实际数据或权重 |
| 证据缺口 | 尚未取得的输入、权限或研究依据 |

## 澄清与假设

每轮只列最关键的 1–3 个问题，给选项或例子；已明确的内容不再询问。

| 事项 | 记录 |
| --- | --- |
| 关键缺口/冲突 | 问题、已查证据、为什么影响技术方案/科学结论/安全；无则写无 |
| 用户决定 | 实际回答及来源；未答保持未答，不代填 |
| 非关键假设 | 默认值、理由及影响范围，与用户决定分开 |
| 受阻操作 | 依赖哪些答案的实现、数据转换、训练、评价或结论 |
| 可继续工作 | 不依赖缺失信息的安全检查与计划 |
| 新证据/恢复 | 运行中新增歧义、再次提问、解决依据和恢复范围 |

无人值守且缺关键信息时记录 NEEDS_USER_INPUT，保留问题并继续独立安全工作。
信息齐全不代表训练、数据访问、预算或硬件已获授权；沿用已有许可，单独记录缺口。
执行后记录实际 commit、检查结果、偏离计划的原因和未完成事项。
