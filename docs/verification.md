# 真实 PR 验证

## 先决条件

远程仓库和基线 CI 已经经授权发布；原生规则集已在用户确认后启用。
需要云端 AI 审核时，Codex GitHub App 和仓库 Code Review 已配置。
缺少条件时标记未执行，不把本地模拟当作远程验证。

## 验收矩阵

| 项目 | 操作 | 所需证据 |
| --- | --- | --- |
| 配置检查 | 首个正常提交执行 CI | 当前 SHA、run URL、job 实际名称和 App ID |
| CI 失败 | PR 仅增加一个无害的重复 Markdown 一级标题 | markdownlint 的真实失败日志 |
| 合并阻断 | 在失败 SHA 读取 PR 和规则状态 | server 返回被 required check 阻止；没有 bypass |
| 修复通过 | 删除重复标题后推送同一 PR | 新 SHA 的所有必需检查成功 |
| 本地 reviewer | 执行 Skill，自主分级调度 | L0 零调用、L1 code、L2 两个独立原生角色；固定 SHA、实际结果和限制 |
| 云端 AI | 合法触发 Codex review | bot 的实际结果及其覆盖的 SHA |
| 单人测试 | 0 个 required approvals | CI 硬门禁通过；双人批准明确未验证 |
| 双人审核 | 未来由另一具备权限者批准 | 无批准时阻断、有效批准后满足规则 |
| 可合并 | 所有已配置条件满足 | 当前 PR 的 mergeable/mergeStateStatus 和 checks |

测试 PR 使用项目已有的研究任务记录或新增 `docs/lab/verification-task.md`，
描述本次基础设施验证目标，明确不作算法结论。首次增加重复一级标题触发
MD025；修复提交只删除多余标题。错误仅存在于测试 PR 的文档历史，不合入
默认分支。不修改算法、真实数据或历史用户修改。

阻断优先用 GitHub 服务端状态证明，不主动尝试可能成功的合并请求。
若要执行真实 merge，需要另行明确授权；最终测试 PR 默认保留供用户审阅。
一次全绿运行不足以证明失败时必然被规则阻止。

## 验证记录

每条证据记录 repo、PR URL、base/head SHA、run URL、check context/App ID、
规则集 ID、UTC 时间、观察结果及限制。不要在公开记录中放真实凭据或
内部部署路径。使用“未执行 / 失败 / 通过 / 不适用”区分状态。

本地工作区基线和用户文件 hash 保留在私有本地 setup 目录；公开报告只写
是否保持，不公布原始内容。实验数据没有全量读取或哈希时不得声称完成
了数据完整性校验。

## 失败处理

CI 失败先定位输入和工具实际输出，只修复本次范围内的问题。
云端 AI 无响应先检查 App 授权、仓库开关、配额和触发条件，不用空 job
伪造成功。规则无法生效时记录套餐/权限/检查上下文原因，保持验证未完成。

回退通过撤销本次新增提交或经确认恢复规则，不重写科研项目历史。

自动审核的隔离任务、原生证据和失败判据见 [分级审核验收](review-dispatch-acceptance.md)。
