## 根因与单变量对照

实际项目 Git 根目录没有被客户端信任，项目配置/角色发现被抑制。
命令行 `-c projects.*.trust_level` 没有解禁该层；独立 opt-in 用户 profile
使其加载。不能把没有生效的信任覆盖当成已加载项目的测试。

| 实际根目录受信任 | 显式 config_file 注册 | 发现两个角色及 agent_type |
| --- | --- | --- |
| 否 | 否 | 否 |
| 否 | 是 | 否 |
| 是 | 是 | 是，并完成一轮原生审核 |
| 是 | 否 | 是，并完成另一轮原生审核 |

因此显式注册机制有效，但不是这份 CLI 的必需条件；不应把强制新增注册文件
作为最小修复，也不应让静态检查拒绝客户端已支持的 standalone 配置。
最终补丁保留原角色 TOML，提供用户本地信任与只读 profile 示例、完善接入和
真实调用证据要求，不将本机路径或个人信任提交进项目。

## 实际审核结果及范围

- Scientific Reviewer：在科学证据与治理范围内未提出可行动问题；指出没有
  实际实验、CI/门禁运行记录和中央源内容，不能由此评估算法复现或实验效度。
- Code Reviewer：在限定的 15 个协作文件中未提出可行动问题；没有宣称验证了
  网络依赖、实际远程工作流或所有客户端的加载行为。
- 两者只读取固定 Git 内容，没有执行测试/钩子/训练，没有数据、网络或硬件
  操作，没有编辑文件或发布 GitHub 内容。

先前显式注册场景的 Code Reviewer 曾提出缺少注册的 P2，同时注明未验证其
加载因果。后续单变量测试和无注册的真实原生调用排除了该因果推断；没有把
该意见直接当作必须增加注册文件的依据，原始结果保留供追溯。

这些审核结论针对固定 main，不是对随后文档补丁或科学算法的额外验收。
静态检查与真实调用分别记录；本地通过不冒充补丁发布后的远程 CI。
