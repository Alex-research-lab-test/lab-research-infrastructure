# GitHub 科研协作

## 从任务到合并

Issue 记录研究问题和验收条件，分支实现最小变更，PR 汇集依据与验证证据。
Actions 负责确定性检查；AI reviewer 提供额外风险发现；有独立审核者时由其
承担批准职责。最终合并由具备权限的人在门禁满足后决定。

研究任务应至少说明输入材料、目标结果、算法/工程改动边界、数据版本、
资源预算与明确的验收方式。模板不能替代尚未取得的论文、数据或实验结果。

## 默认分支规则

本测试阶段提议对 `main` 启用：必须通过 PR、要求真实 `lab-ci` 检查成功、
必需讨论解决、禁止强推和删除、无日常 bypass。所需检查名称及 App ID
必须由首个实际 Actions run 读取，不能凭文档预先声称已生效。

单成员组织从 0 个必需批准开始，以避免自批死锁。CI 失败仍须阻断合并。
有第二名具备写权限的独立成员后，可另行配置 1 个必需批准、废弃旧批准，
并测试最新提交后重新审核的行为。不借用机器人账号伪装真人审核。

## 权限和 CI

- 默认 PR workflow 使用 `contents: read`，checkout 不持久化凭据。
- 普通 PR 仅在 GitHub hosted runner 执行，不自动连入实验室机器。
- 不用 `pull_request_target` 加载和执行 PR 分支代码。
- CI 下载工具使用固定版本/commit，归档核对固定 SHA-256。
- 不为了本次测试提高组织默认权限、增加写 token 或授予自动批准权限。
- 工作流和规则变更也是审核对象。基础 status checks 不能防止有权限的人
  修改工作流含义；如需更强组织治理，单独评估原生能力和套餐。

## 规范更新

项目保存中央仓库来源 commit 及本地适配说明。更新模板需比较新旧版本，
通过项目 PR 合入，不能直接覆盖已有 AGENTS、CI 或用户修改。

默认不自动邀请成员、不自动安装 App、不自动合并 PR。
失败时保留提交、运行链接和原因；回退只处理本次新增内容。
